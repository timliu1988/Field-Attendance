# 出勤打卡（field-attendance）v1.3 — 架設與使用說明

## 檔案說明
| 檔案 | 用途 |
|---|---|
| `index.html` | 整個 App（選名字登入、打卡、請假／半天假、出勤紀錄補登、批次登記、月報表匯出） |
| `config.js` | **唯一需要修改的檔案**：公司名稱、上下班與午休時間、半天班時段、示範名單、Firebase 設定 |
| `firestore.rules` | 資料庫權限規則，正式版時貼到 Firebase Console |
| `manifest.webmanifest`、`sw.js`、`icons/` | 加到手機主畫面與離線用，不用改 |

## 兩種模式
- **示範模式**：`config.js` 的 `firebase` 是 `null`。每個人試用的資料只存在自己手機的瀏覽器，不會寫到 GitHub 或任何雲端，適合說明會試用。
- **正式模式**：`firebase` 填入設定後，大家的打卡會存在同一個 Firebase 資料庫，月報表才會有全員資料。

## 一、把示範版放上 GitHub（說明會用）
全部在 GitHub 網頁上操作，不需要安裝任何軟體。

### 1. 解壓縮並確認名單
1. 解壓縮 `field-attendance-v1.3.zip`，裡面直接就是 `index.html`、`config.js`、`icons` 資料夾等檔案。
2. 用記事本打開 `config.js`，確認 `demoNames` 是要顯示的同事名單（已預先填好），`firebase` 保持 `null`。

### 2. 建立 repository（專案）
1. 到 https://github.com 登入（沒有帳號先免費註冊）。
2. 右上角「**＋**」→「**New repository**」。
3. **Repository name** 填 `field-attendance`。
4. 選「**Public**」（免費帳號的 GitHub Pages 需要公開）。
5. 下方的「Add a README file」**不要勾**。
6. 按「**Create repository**」。

### 3. 上傳檔案
1. 在剛建好的頁面，點中間的「**uploading an existing file**」連結。
2. 打開解壓縮後的資料夾，**全選裡面的檔案和 `icons` 資料夾**，一起拖進網頁的上傳框。
   - 要拖的是「資料夾裡面的東西」，不是外層資料夾本身；拖完上傳清單裡要看得到 `index.html` 在最上層。
3. 等清單都跑完，按下方綠色「**Commit changes**」。

### 4. 開啟 GitHub Pages
1. repository 上方選單點「**Settings**」→ 左側「**Pages**」。
2. 「Build and deployment」的 **Source** 選「**Deploy from a branch**」。
3. **Branch** 選「**main**」、資料夾選「**/ (root)**」→ 按「**Save**」。
4. 等 1～3 分鐘後重新整理這一頁，上方會出現網址：`https://你的帳號.github.io/field-attendance/`。
5. 用手機打開這個網址，右上角有「示範模式」字樣、名單是同事名字，就完成了。

### 5. 分享給同事
- 把網址貼到群組，提醒大家**用 Safari／Chrome 打開，不要用 LINE 內建瀏覽器**（LINE 裡點右上角選單 →「用預設瀏覽器開啟」）。
- 想用 QR code：電腦用 Chrome 打開網址 → 網址列右邊的分享圖示 →「建立 QR code」，投影在說明會上讓大家掃。

> 注意：Public repository 任何人都看得到程式和 `config.js` 裡的名單，建議名單只放英文名，不要放全名或員編。

## 二、改成正式版（說明會後）
不用刪掉 GitHub 重傳，只要改 `config.js`。

### 1. 建立 Firebase（免費 Spark 方案即可）
1. 到 https://console.firebase.google.com → 新增專案。
2. **Authentication** → 開始使用 → 登入方式 → 啟用「**匿名**」（不需要 email 帳號）。
3. **Firestore Database** → 建立資料庫 → 地區選 `asia-east1（台灣）` → 正式版模式。
4. Firestore →「**規則**」：貼上 `firestore.rules` 全部內容 → 發布。
5. 專案設定（齒輪）→ 一般 → 你的應用程式 → 新增「網頁」應用程式 → 複製 `firebaseConfig` 的內容。
6. Authentication → 設定 →「**授權網域**」→ 加入 `你的帳號.github.io`。

### 2. 在 GitHub 上修改 config.js
1. 打開 repository → 點 `config.js` → 右上角鉛筆圖示（**Edit this file**）。
2. 把 `firebase: null` 改成 `firebase: { …貼上剛才複製的內容… }`。
3. 按「**Commit changes**」。等 1～5 分鐘網站更新。

### 3. 第一次使用正式版
1. 同事打開 App 會**自動清掉手機裡的示範資料**，回到選名字的畫面，不用自己清除瀏覽器資料。
   還看到「示範模式」的話，把 App 完全關掉再打開一次（手機要有網路）。
2. 由一人先依序在「名單裡沒有我？」輸入同事名字加入；每加一個會跳出設定密碼，按「取消」即可，名字會留在名單上。
3. 每位同事點自己的名字 → **重新設定 4 位數密碼**（示範時設的密碼不會帶過來）。

## 三、之後更新版本
1. 解壓縮新版 zip。
2. **先保留 GitHub 上現有的 `config.js`**（裡面有 Firebase 設定），上傳時不要用新版的 `config.js` 蓋掉；如果新版 `config.js` 有新增設定，照說明手動加到 GitHub 上的那份。
3. repository →「**Add file**」→「**Upload files**」→ 拖入其他檔案（同名會自動覆蓋）→「Commit changes」。

## 四、加到手機主畫面
- **iPhone**：Safari（或 iOS 16.4 以上的 Chrome／Edge）→ 分享 →「加入主畫面」→「加入」。
- **Android**：Chrome →「⋮」→「加到主畫面」或「安裝應用程式」→「安裝」；三星網際網路在下方「≡」選單。
- 同一支手機建議固定用同一個瀏覽器；換瀏覽器開，要再輸入一次密碼（紀錄不會不見）。

## 五、使用方式
- **打卡**：選「出勤」→ 上班打卡／下班打卡，記錄按下當時的手機時間。
- **請假**：點假別 → 登記今日。國定假日、天災假可在備註寫「端午」「颱風假」，總表會直接顯示。
- **半天假**：休假、事假、病假、特休、公假、天災假選好後，「請假時段」可選上午或下午：
  - 請上午假 → 自動帶入下午班 13:30–17:30；請下午假 → 自動帶入上午班 08:30–12:30（時間可再修改）。
  - 統計算成請假 0.5 天、出勤 0.5 天；總表顯示「特休(上)」「病假(下)」。
- **出勤紀錄**：點任何一天可補填或修改；未打卡的平日會顯示紅字「未打卡，點此補登」。
- **批次登記**：一次把多個未登記的日子套用約定時間或同一假別（也可選上午／下午）。
- **月報表**（所有人可用）：選月份 → 匯出 Excel，A4 橫式一頁；值日生匯出後送 DocuSign 簽核。
- **人員名單**：在「月報表」頁下方可改名、停用離職同仁。
- 換手機或換人：右上角「切換使用者」；改密碼：右上角「修改密碼」。

## 六、密碼
- 每人一組 4 位數密碼，只存雜湊值，任何人（包括管理者）都看不到原始數字。
- 正式版中，沒通過密碼的手機，資料庫會直接拒絕修改那個人的紀錄（規則寫在 `firestore.rules`）。
- **忘記密碼重設**（由管理者在 Firebase Console 操作）：
  1. Firestore → `people` 集合，找到該同仁名字那一筆，記下文件 ID。
  2. 刪除 `pins` 集合裡同一個 ID 的文件。
  3. 回到 `people` 那一筆，把 `hasPin` 改成 `false`（或刪掉這個欄位）。
  4. 同仁重新打開 App 點名字，就能設定新密碼。
- 4 位數密碼的目的是防止同事誤用或冒用，不是銀行等級的保護。

## 七、時數計算
- 出勤時數＝下班－上班－與午休（12:30–13:30）重疊的時間。
- 全天正常範圍 8:00–8:30，半天 4:00–4:15；超出範圍會在 App 與總表標紅提醒。
- 這些時間都可以在 `config.js` 調整。
